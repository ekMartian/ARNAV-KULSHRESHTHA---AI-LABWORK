# Laboratory – Logical Reasoning for Planning

## Task 0: Understand the Planning Problem
(a) **Initial state $I$**: `{At(Robot, A), At(Package, A)}`
(b) **Goal $G$**: `{At(Package, C)}`
(c) **Available actions**: `Move(A, B)`, `Move(B, A)`, `Move(B, C)`, `Move(C, B)`, `PickUp(Package, X)`, `Drop(Package, X)` where X is A, B, or C.
(d) **Preconditions and effects**: 
* `Move(X, Y)`: pre=`At(Robot, X)`, eff=`At(Robot, Y), ¬At(Robot, X)`
* `PickUp(Package, X)`: pre=`At(Robot, X), At(Package, X)`, eff=`Holding(Package), ¬At(Package, X)`
* `Drop(Package, X)`: pre=`At(Robot, X), Holding(Package)`, eff=`At(Package, X), ¬Holding(Package)`

**Question**: 
Starting from $I$, is `PickUp(Package, A)` applicable? **Yes**, because both `At(Robot, A)` and `At(Package, A)` are in $I$.
What about `Drop(Package, C)`? **No**, because it requires `At(Robot, C)` and `Holding(Package)`, neither of which are in $I$.

## Task 4: Logic and Search
**Where each is used:**
* **Logic** determines what is possible: It checks $S \models Preconditions(a)$ to filter applicable actions, and applies effects to compute the new state $S'$.
* **Search** determines what to try: It systematically explores the branching paths (using BFS) to find a sequence that eventually satisfies the goal state.

Current state $\rightarrow$ Check action preconditions $\rightarrow$ **Filter applicable actions** $\rightarrow$ Generate successor state $\rightarrow$ Search over alternatives $\rightarrow$ Goal?

## Task 6: Prolog as a Plan Verifier
(a) Prolog returns `true` for `can_move(a,b)` because it explicitly matches the fact `connected(a,b)`.
(b) It does not establish `can_move(a,c)` because there is no fact `connected(a,c)`, and Prolog assumes closed-world negation (if it can't prove it, it's false).
(c) The rule `can_move(X,Y) :- connected(X,Y).` perfectly encodes the logical implication $Connected(X, Y) \rightarrow CanMove(X, Y)$.

## Task 8: Connect Prolog to Logical Reasoning
The query `?- reduce_speed.` succeeds because `reduce_speed` is implied by `slippery`, which is implied by `wet_road`, which is a known fact.
**Logical reasoning sequence:**
`wet_road` $\Rightarrow$ `slippery :- wet_road` $\Rightarrow$ `reduce_speed :- slippery` $\Rightarrow$ `reduce_speed`.

## 7.2 Reflection Questions
1. A fact is unconditionally true (e.g., `connected(a,b)`). A rule is conditionally true based on whether its body can be proven (e.g., `can_move(X,Y) :- connected(X,Y)`).
2. A query asks the Prolog inference engine to attempt to derive the queried statement using the facts and rules in the knowledge base.
3. Using Prolog verifies that the sequence of actions generated by a Python program actually respects the physical rules of the domain without relying on the Python code's own logic, providing an independent check.
4. An independent verifier provides a guarantee of correctness that is mathematically sound, avoiding the risk of the LLM hallucinating a physically impossible action that just "sounds right".
